# Канонические инструкции проекта для AI-агентов

Этот файл является главным набором постоянных правил для AI, работающего в проекте. Пользовательские инструкции имеют приоритет. При неоднозначном или рискованном конфликте сначала объясни его и запроси решение.

## Команды управления

- Отдельное сообщение `START` при незавершённой настройке запускает `prompts/00-start.md`.
- `START` после завершённой настройки показывает краткий статус и не перезаписывает документы.
- Отдельная команда `ПРИМЕНИТЬ` применяется только после полного опроса и запускает этап применения из `prompts/01-initialize-project.md`.
- Отдельная команда `ИЗМЕНИТЬ ПРАВИЛА ПРОЕКТА` запускает повторный опрос без автоматического удаления прежних решений.
- Отдельная команда `закрываем сессию` запускает `prompts/06-close-session.md` и считается явным разрешением на безопасный commit и обычный push в заранее согласованный приватный `origin`.
- Упоминание этих фраз внутри обычного текста не является командой.

## Перед любой работой

Прочитай в таком порядке:

1. `AGENTS.md`.
2. `docs/PROJECT_POLICY.md`.
3. `docs/PROJECT_CONTEXT.md`.
4. `docs/STATUS.md`.
5. Актуальные принятые решения в `docs/decisions/`.
6. Последний подходящий файл в `logs/sessions/`, если он нужен для текущей задачи.
7. Проверь Git status, если Git инициализирован.

Если инициализация не завершена, не начинай обычную проектную работу. Предложи `START`.

## Источники истины

- Текущая работа и следующий шаг: `docs/STATUS.md`.
- Стабильная цель и границы: `docs/PROJECT_CONTEXT.md`.
- Действующие правила: этот файл и `docs/PROJECT_POLICY.md`.
- Причины существенных решений: `docs/decisions/`.
- Фактическая история файлов: Git.
- Session logs являются историей, а не текущим состоянием.
- Не полагайся на чат как на единственную память.

## Рабочие правила

- Работай только в корне открытого проекта и его дочерних каталогах.
- Не создавай дополнительную папку с именем проекта внутри уже открытого корня.
- Соблюдай границы текущей задачи и сохраняй пользовательские изменения.
- Для чтения, обзора и обсуждения не изменяй проект без явного запроса, кроме подтверждённой записи ответов во время `START`.
- Не удаляй, не перезаписывай историю, не публикуй, не деплой и не отправляй данные третьим лицам без явного разрешения.
- Не показывай и не записывай значения секретов.
- Не копируй полный вывод терминала в session log. Сохраняй только полезный итог и безопасные названия команд.
- Запускай релевантные проверки. Если проверка пропущена, укажи причину.

## Документирование

- `docs/STATUS.md` обновляется при завершении содержательной сессии.
- Session log создаётся в формате `YYYY-MM-DD-HHMM-краткая-тема.md`.
- `docs/CHANGELOG.md` обновляется только при значимом для пользователя изменении.
- Новое решение создаётся только при существенном выборе архитектуры, инструмента, структуры, риска или политики.
- Не создавай `logs/actions.md` и не дублируй один и тот же отчёт во всех документах.

## Git и GitHub

- По умолчанию сохраняй все файлы проекта, кроме путей, явно исключённых как секретные.
- Перед commit проверяй staged-состав, содержимое на секреты и размеры новых/изменённых файлов.
- Предупреждай о файлах от 50 MiB или от порога, установленного в политике проекта.
- Решение о Git LFS, сжатии, внешнем хранилище или исключении принимает пользователь.
- GitHub-репозиторий должен быть приватным.
- Не используй force push, не переписывай историю и не меняй `origin` автоматически.
- Не создавай пустой commit.
- Если tests не прошли, следуй режиму из `docs/PROJECT_POLICY.md`; в персональном backup-режиме сохрани состояние и явно отметь ошибку.

## Автоматическое закрытие

После отдельной команды `закрываем сессию` не спрашивай дополнительного подтверждения для документирования, commit и обычного push, если одновременно выполнены условия:

- `origin` заранее согласован;
- репозиторий приватный;
- нет подозрения на секрет;
- нет нерешённого крупного файла;
- не требуется force push, удаление, rebase с риском или смена remote;
- авторизация действительна.

Если условие нарушено, остановись безопасно и выдай отчёт о препятствии.

## Финальный отчёт задачи

Сообщи:

1. Что сделано.
2. Какие файлы изменены.
3. Какие проверки выполнены.
4. Какие риски или ограничения остались.
5. Какой следующий шаг.
