# Skills, плагины и MCP

Статус документа: **ОЖИДАЕТ ЗАПОЛНЕНИЯ ЧЕРЕЗ START**

Реестр расширений проекта и инструкция по их восстановлению. Здесь хранятся названия, источники, версии и проверки — но никогда не токены, пароли и OAuth-сессии.

## Базовый принцип

Starter Kit не требует обязательных расширений. Каталоги и конфигурации создаются только тогда, когда пользователь выбрал конкретное расширение или проект уже содержит его безопасную конфигурацию. Обнаружение расширения не означает разрешения на установку, обновление или авторизацию.

## Где что хранится

Пути зависят от AI-клиента. Перед добавлением сверьтесь с актуальной документацией клиента.

| Тип | Хранится в проекте (Git) | Восстанавливается отдельно |
|---|---|---|
| Project Skill | Codex: `.agents/skills/<имя>/`; Claude Code: `.claude/skills/<имя>/` | Системные зависимости и доступы |
| Project MCP | Codex: `.codex/config.toml`; Claude Code: `.mcp.json`; Cursor: `.cursor/mcp.json` — только безопасная конфигурация | Доверие к проекту, зависимости, вход, секретные переменные |
| Project plugin | Исходники плагина, если он принадлежит проекту | Установка, кэш, OAuth |
| User Skill, глобальный MCP | Только запись в этом реестре: источник, версия, инструкция | Установка на конкретном компьютере или аккаунте |
| Команды Starter Kit для Claude Code | `.claude/commands/kit-*.md` | Ничего — работают сразу после копирования |

Успешный clone не означает, что все расширения установлены и авторизованы.

## Реестр

Обязательных расширений по умолчанию нет. При `START` добавьте строку на каждое выбранное или обнаруженное расширение.

| Название | Тип | Обязательно | Источник и версия | Конфигурация в проекте | Как восстановить и проверить | Статус |
|---|---|---|---|---|---|---|
| Нет | — | — | — | — | — | Не выбрано |

Статусы: `НЕ ВЫБРАНО`, `ОБНАРУЖЕНО`, `НАСТРОЕНО`, `ОТЛОЖЕНО`, `ТРЕБУЕТ УСТАНОВКИ`, `ТРЕБУЕТ АВТОРИЗАЦИИ`, `НЕ ПРИМЕНЯЕТСЯ`.

## Правила добавления

1. Точное название, официальный источник, версия или commit.
2. Область: проектная или пользовательская/глобальная.
3. В Git — только принадлежащие проекту исходники и безопасная конфигурация.
4. Секреты — только через переменные окружения или защищённое хранилище; в Git — лишь имена переменных.
5. Короткая команда или наблюдаемая проверка работоспособности.
6. Не создавайте пустые каталоги расширений заранее.

## Проверка после clone или смены агента

1. Прочитайте реестр до установки чего-либо.
2. Проверьте, что project-local файлы пришли из Git.
3. Установите пользовательские расширения и зависимости из зафиксированных источников — с разрешения пользователя.
4. Доверяйте проектной MCP-конфигурации только после проверки её содержимого.
5. Восстановите секретные переменные, не выводя значения.
6. Выполните проверку из каждой строки и обновите статус.

Если расширение недоступно, агент сообщает, какая функция потеряна и есть ли безопасная альтернатива. Источник и версия молча не меняются.
