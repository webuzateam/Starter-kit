# Настройка и применение

## Общие правила

- Охвати все 13 блоков `docs/PROJECT_QUESTIONNAIRE.md` выбранным способом. После первого записанного блока установи статус `В ПРОЦЕССЕ`.
- У каждого значимого значения — источник, у каждого правила — статус (словарь в `docs/PROJECT_POLICY.md`). Вывод агента не называй подтверждённым.
- Противоречие, влияющее на безопасность или текущий результат, разреши до применения. Низкорисковое неизвестное — отложи.
- Неизвестное разрешение на рискованное действие — всегда `ЗАБЛОКИРОВАНО`.

## Режимы

**С сопровождением.** Вопросы по 3–5 за раз, карточками. Блоки, где хватает рекомендаций, покажи одной сводкой «принять / изменить».

**Быстрый.** Задай только вопросы ★. Остальное заполни безопасными значениями и не скрывай их в сводке.

**Без брифа.**

1. Read-only анализ структуры, README, конфигураций, исходников, документов и Git-состояния.
2. Записывай только факты с наблюдаемым основанием (`ВЫВЕДЕНО` + путь).
3. Для обратимых внутренних настроек — безопасные значения (`ПО УМОЛЧАНИЮ`).
4. Неизвестное — `ОТЛОЖЕНО`, разрешения на рискованные действия — `ЗАБЛОКИРОВАНО`.
5. Рабочее название и описание сформируй из контекста и отметь как `ВЫВЕДЕНО`.
6. Вопрос задавай только при противоречии, мешающем безопасной настройке.

## Итоговая сводка

Когда все блоки охвачены:

1. Установи статус `ОЖИДАЕТ ПРИМЕНЕНИЯ`.
2. Покажи: режим; паспорт проекта с источниками; принятые и изменённые правила; отложенные решения и заблокированные действия; языковую и Git-политику; секретные пути; порог крупного файла; команды проверок; предварительный уровень готовности.
3. Перечисли файлы, которые будут заполнены, включая полную замену `README.md`.
4. Предупреди: создание репозитория, публикация и deploy на этом этапе не выполняются.
5. Попроси отдельную команду `ПРИМЕНИТЬ`.

## После команды ПРИМЕНИТЬ

Команда разрешает записать конфигурацию в файлы проекта. Она не разрешает создавать репозиторий, публиковать, деплоить или выполнять другие внешние действия.

1. `docs/PROJECT_CONTEXT.md` — без выдуманных фактов, с источниками.
2. `README.md` — **полностью замени** на README проекта: название, что это, для кого, текущий этап, структура, запуск и проверки (неизвестное — так и пометь), ссылки на `docs/PROJECT_CONTEXT.md`, `docs/STATUS.md` и `docs/HOW_IT_WORKS.md`. Заголовок `AI Project Starter Kit` не сохраняй. Можно добавить строку «Проект ведётся с помощью AI Project Starter Kit».
3. `docs/PROJECT_POLICY.md` — статус и источник каждого правила; для заблокированных — конкретное действие.
4. `AGENTS.md` — заполни только раздел между маркерами `PROJECT-RULES`; защитные правила не удаляй.
5. `.gitignore` — добавь подтверждённые или обнаруженные секретные пути и решения по кэшу и зависимостям. Предполагаемый путь без основания не добавляй.
6. `.env.example` — только имена переменных. `docs/SECRETS.md` — карта без значений.
7. `.starter-kit/config` и таблица в `docs/GIT_POLICY.md` — известные значения; неизвестные оставь пустыми (тогда push будет заблокирован скриптом).
8. `docs/INTEGRATIONS.md` — найденные или выбранные расширения либо явная запись «не обнаружены».
9. `docs/RECOVERY.md` — дополнительные материалы для восстановления, если они есть.
10. `docs/decisions/0001-правила-и-структура-проекта.md` по `DECISION_TEMPLATE.md` и строка в индексе `docs/decisions/README.md`.
11. `docs/STATUS.md` — дата, режим, уровень готовности, текущая работа, отложенные решения, заблокированные действия, следующий шаг.
12. Статус опроса `ЗАВЕРШЕНА` (означает «сводка применена», а не «всё известно»).
13. Аудит по `prompts/02-audit-project.md`; найденные пробелы в рамках применённой сводки исправь.
14. `docs/INITIALIZATION_REPORT.md`.

## Финальный отчёт

Проект и корень; режим; количество данных по источникам; принятые и изменённые правила; отложенные решения; заблокированные действия; результат аудита; уровень готовности; что дальше — обычно рабочая задача или настройка Git по `prompts/03-setup-git-github.md`.
