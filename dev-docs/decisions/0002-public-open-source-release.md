# 0002 — Публичный open-source релиз

- Дата: 2026-10-08.
- Статус: Принято.
- Источник: `ПОДТВЕРЖДЕНО` — решение владельца выпустить Starter Kit бесплатно и открыто на GitHub.
- Ответственный: владелец Starter Kit.

## Контекст

Starter Kit развивался как приватный репозиторий, сайт хранился отдельно без Git (архивы `tar.gz`) и публиковался вручную. Для публичного релиза обнаружены проблемы:

- мастер-шаблон определялся по `origin = webuzateam/Starter-kit` — у любого, кто клонирует публичный репозиторий, агент отказался бы настраивать проект;
- правило «GitHub только приватный» противоречило публичному распространению и проектам с открытым кодом;
- в шаблон попадали материалы разработки самого kit (ADR 0001, changelog, дата статуса);
- не было лицензии, установки одной командой, механизма обновления, автоматических проверок;
- проверка секретов полностью зависела от внимательности модели;
- одни и те же правила пересказывались в 6–7 файлах, что повышало риск противоречий и расход токенов.

## Решение

1. **Лицензия MIT.** Копия лицензии лежит в `template/.starter-kit/LICENSE`, чтобы не выглядеть лицензией проекта пользователя.
2. **Монорепозиторий:** `template/` (продукт), `site/` (сайт), `scripts/` (проверки), `dev-docs/` (решения kit). Сайт переходит под Git; архивы больше не нужны.
3. **Распространение:** `npx degit webuzateam/Starter-kit/template` и zip-архив шаблона в GitHub Releases. Клон всего репозитория проектом не является.
4. **Маркер мастер-шаблона:** файл `.starter-kit-source` в корне репозитория. Он не входит в `template/` и не копируется пользователям.
5. **Видимость выбирает пользователь:** приватный — рекомендация по умолчанию, публичный — по явному выбору с проверкой всей истории.
6. **Детерминированные проверки:** `.starter-kit/preflight.sh` (bash 3.2+, без зависимостей) и машиночитаемый `.starter-kit/config`. Агент вызывает скрипт, а не полагается на собственный просмотр файлов. `gitleaks` используется, если установлен.
7. **Одно правило — одно место:** команды и границы — `template/AGENTS.md`, словарь статусов — `template/docs/PROJECT_POLICY.md`.
8. **Обновление:** версия в `.starter-kit/VERSION`, сценарий `prompts/08-upgrade.md` с таблицей владения файлами, маркеры `PROJECT-RULES` в `AGENTS.md`.
9. **CI/CD:** проверки согласованности и тесты на каждый PR, деплой сайта и сборка релиза через GitHub Actions.

## Рассмотренные варианты

- *Два отдельных репозитория (шаблон и сайт).* Отклонено: сайт описывает файлы шаблона, и их согласованность проще проверять в одном CI.
- *Шаблон в корне репозитория (GitHub Template Repository).* Отклонено: тогда в проект пользователя попадали бы сайт, CI и материалы разработки.
- *Только приватные репозитории.* Отклонено: противоречит open-source-распространению и нуждам пользователей.

## Последствия

- Проще: установка, обновление, проверка секретов, участие сообщества.
- Сложнее: изменения путей шаблона требуют обновления сайта — это контролирует `scripts/check-consistency.mjs`.
- Существующие проекты на версиях 0.x могут перейти на 1.0.0 через `ОБНОВИТЬ STARTER KIT`; `origin`-правило мастер-шаблона в них больше не действует.

## Откат или замена

Заменяется новым решением. Публикацию репозитория откатить нельзя (код мог быть скопирован), поэтому перед сменой видимости проверяется вся история на секреты.
