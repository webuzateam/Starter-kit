# Skills, плагины и MCP

Статус документа: **ОЖИДАЕТ ЗАПОЛНЕНИЯ ЧЕРЕЗ START**

Этот файл — реестр расширений проекта и инструкция по их восстановлению. Он хранит описания, источники, версии и проверки, но никогда не хранит токены, пароли, OAuth-сессии или другие секреты.

## Базовый принцип

Starter kit не требует обязательных расширений. Каталоги и конфигурации создаются только тогда, когда пользователь выбрал конкретный Skill, плагин или MCP-сервер. Это сохраняет шаблон лёгким и не привязывает его к одному AI-агенту.

## Что переносится через Git

| Тип | Что можно хранить в проекте | Что восстанавливается отдельно |
|---|---|---|
| Project Skill | `.agents/skills/<имя>/SKILL.md` и нужные ресурсы | Системные зависимости и доступы, если они нужны |
| User Skill | Только ссылка, версия и инструкция в этом реестре | Установка из `~/.agents/skills` или другого пользовательского каталога |
| Plugin | Исходники плагина и project marketplace, если они принадлежат проекту | Установленное состояние, кэш, OAuth и авторизация |
| Project MCP | Безопасная конфигурация в `.codex/config.toml` | Доверие к проекту, зависимости, вход и секретные переменные |
| Global MCP | Название, источник и инструкция восстановления | Глобальная конфигурация конкретного компьютера или аккаунта |

Project Skills автоматически обнаруживаются совместимыми агентами из `.agents/skills/`. Проектная MCP-конфигурация применяется только в доверенном проекте. Поддержка плагинов и расположение глобальных настроек зависят от используемого AI-клиента, поэтому успешный clone не означает автоматическую установку и авторизацию всех расширений.

## Реестр

Обязательных расширений по умолчанию нет. При `START` добавьте по одной строке на каждое выбранное расширение.

| Название | Тип | Обязательность | Область | Источник и версия | Конфигурация в проекте | Как восстановить и проверить | Статус |
|---|---|---|---|---|---|---|---|
| Нет | — | — | — | — | — | — | Не выбрано |

Возможные статусы: `НЕ ВЫБРАНО`, `НАСТРОЕНО`, `ТРЕБУЕТ УСТАНОВКИ`, `ТРЕБУЕТ АВТОРИЗАЦИИ`, `НЕ ПРИМЕНЯЕТСЯ`.

## Правила добавления

1. Зафиксируйте точное название, официальный источник и по возможности версию или commit.
2. Определите область: проектная или пользовательская/глобальная.
3. Добавляйте в Git только принадлежащие проекту исходники и безопасную конфигурацию.
4. Передавайте секреты только через переменные окружения или защищённое хранилище. В Git записывайте лишь имена переменных.
5. Запишите короткую команду или наблюдаемую проверку работоспособности.
6. Не создавайте пустые `.agents/skills/`, `plugins/` или `.codex/`, пока они не нужны проекту.

## Проверка после clone или смены агента

1. Прочитайте этот реестр до установки расширений.
2. Проверьте наличие project-local файлов, которые должны прийти из Git.
3. Установите отдельно перечисленные пользовательские Skills, плагины и системные зависимости из зафиксированных источников.
4. Доверьте проект только после проверки содержимого `.codex/config.toml`.
5. Восстановите секретные переменные без вывода значений в чат или отчёт.
6. Выполните проверку из каждой строки реестра и обновите её статус.

Если расширение недоступно, агент сначала сообщает, какая функция потеряна и есть ли безопасный альтернативный путь. Он не заменяет источник и не обновляет версию молча.
