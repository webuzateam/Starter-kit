# Политика Git и GitHub

## Назначение

Git хранит историю проекта и создаёт удалённую приватную копию всех значимых данных. Это не ветка разработки и не временный DEV-контур: удалённый репозиторий является устойчивой копией состояния проекта.

## Базовые правила

- Один самостоятельный проект — один Git-репозиторий.
- GitHub-репозиторий — только приватный.
- Значимые исходники, документы, данные, outputs и невоспроизводимые результаты добавляются, если они не исключены принятой политикой.
- Секреты всегда исключаются.
- Системные метаданные вроде `.DS_Store` не являются памятью проекта и исключаются в мастер-шаблоне.
- Кэш, сборки и воспроизводимые зависимости рассматриваются во время `START`: их не скрывают и не добавляют автоматически без решения пользователя.
- `.gitignore` не используется для молчаливого сокрытия содержательных материалов.
- `origin`, владелец, репозиторий и основная ветка фиксируются после настройки.
- Force push, переписывание истории, удаление refs и смена remote не выполняются автоматически.

## Первичная настройка

До `git init` агент:

1. Проверяет фактический корень.
2. Проверяет отсутствие родительского или вложенного репозитория.
3. Проверяет существующие remotes.
4. Проверяет, что сводка START применена, уровень готовности указан, а Git-действия не заблокированы отложенными решениями.
5. Проверяет, что корневой `README.md` описывает конкретный проект, а не мастер-шаблон.
6. Проверяет `.gitignore`, обнаруженные secret-пути и содержимое файлов; неизвестность в карте секретов не считается успешной проверкой.
7. Проверяет согласованную политику кэша и воспроизводимых файлов.
8. Проверяет размеры файлов.
9. Проверяет наличие Git, GitHub CLI и авторизации.

Установка системных инструментов требует разрешения. Для GitHub используется безопасная браузерная авторизация; токен не запрашивается в чате.

Для нового проекта по умолчанию предлагается ветка `main`. Первый commit и push запрещены, пока `README.md` остаётся README мастер-шаблона или не выполнены контрольные точки Git, секретов и крупных файлов. Режим без брифа и команда `ПРИМЕНИТЬ` сами по себе не подтверждают владельца, имя репозитория, remote или первый push. Перед созданием приватного GitHub-репозитория и первым push пользователь получает сводку и подтверждает действие.

## Подготовка commit

Перед commit агент:

- проверяет `git status`;
- проверяет все новые, изменённые и удалённые файлы;
- ищет секреты без вывода значений;
- проверяет размеры;
- добавляет все значимые изменения согласно принятой политике;
- проверяет staged diff и ошибки пробелов;
- создаёт содержательное сообщение commit.

Пустые commits не создаются.

## Крупные файлы

Предупреждение по умолчанию: 50 MiB. Проверка выполняется до commit. Пользователь выбирает обычный Git, Git LFS, сжатие, разделение, внешнее хранилище, исключение или отмену синхронизации.

Агент не включает Git LFS, не исключает файл и не переписывает историю самостоятельно.

## Автоматическое закрытие

Команда `закрываем сессию` является явным постоянным разрешением на commit и обычный push без повторного вопроса, если remote и ветка заранее согласованы, репозиторий приватный, секреты не обнаружены и не требуется рискованная операция.

Автоматизация останавливается при:

- подозрении на секрет;
- нерешённом крупном файле;
- публичной видимости;
- изменении `origin`;
- конфликте или расходящейся истории;
- необходимости force push;
- потере авторизации;
- отклонении файла GitHub.

## Проверка результата

После push агент подтверждает ветку, commit, remote, успешную отправку и чистое рабочее дерево. Ignored-секреты могут оставаться локально; их значения не показываются.
