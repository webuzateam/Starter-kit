# Восстановление проекта

Используйте этот документ после потери AI-чата, смены агента или аккаунта, нового clone или длительного перерыва.

## Порядок реконструкции

Новый агент обязан:

1. Прочитать `AGENTS.md`.
2. Прочитать `docs/PROJECT_POLICY.md`.
3. Прочитать `docs/PROJECT_CONTEXT.md`.
4. Прочитать `docs/STATUS.md`.
5. Прочитать индекс и актуальные решения в `docs/decisions/`.
6. Прочитать последний подходящий session log.
7. Проверить корень проекта и Git status.
8. Сверить ветку, последний commit и `origin`, если Git настроен.
9. Проверить наличие обязательных файлов без раскрытия секретов.
10. Составить отчёт до любых изменений.

## Отчёт реконструкции

Агент сообщает:

- что это за проект;
- цель и границы;
- текущий этап;
- последний завершённый шаг;
- открытые задачи;
- важные решения;
- риски и блокеры;
- Git-состояние;
- первый безопасный следующий шаг.

## Запрет до реконструкции

Не редактировать файлы, не устанавливать зависимости, не выполнять commit, push или внешние действия, пока отчёт реконструкции не готов.

## Проверка восстановления

Recovery drill успешен, если новый агент без старого чата может объяснить проект, назвать важные файлы и предложить корректный следующий шаг. Результат и дата теста записываются в `docs/INITIALIZATION_REPORT.md` или новый session log.
