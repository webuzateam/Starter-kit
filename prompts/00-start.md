# Команда START

Этот сценарий запускается только отдельным сообщением `START`.

Используй протокол **START v2** ровно с тремя режимами: **с сопровождением**, **быстрый**, **без брифа**. Не предлагай другие режимы.

## 1. Определи состояние

Прочитай `README.md`, `AGENTS.md`, `docs/PROJECT_QUESTIONNAIRE.md` и `docs/STATUS.md`. Проверь фактический корень, наличие лишней вложенной папки и существующего Git-репозитория. На этом этапе ничего не изменяй.

Если настройка завершена, не запускай настройку повторно. Кратко сообщи цель, режим START, уровень готовности, относящиеся к следующему шагу контрольные точки и предложи начать рабочую сессию. Для пересмотра правил предложи команду `ИЗМЕНИТЬ ПРАВИЛА ПРОЕКТА`.

Если настройка `В ПРОЦЕССЕ`, продолжи ранее выбранный режим с сохранённого блока. Если статус `ОЖИДАЕТ ПРИМЕНЕНИЯ`, не повторяй вопросы или анализ: покажи актуальную сводку и напомни отдельную команду `ПРИМЕНИТЬ`.

## 2. Покажи краткий отчёт starter kit

Объясни простым языком:

- зачем система хранит память в файлах;
- роль `README.md`, `AGENTS.md`, `PROJECT_CONTEXT.md`, `PROJECT_POLICY.md`, `STATUS.md`, `INTEGRATIONS.md`, `decisions/`, `sessions/`, `prompts/`, `src/` и `outputs/`;
- последовательность `START → выбор режима → сводка → ПРИМЕНИТЬ → аудит → работа → закрываем сессию`;
- что Git сохраняет значимые данные, секреты всегда исключены, а политика кэша и воспроизводимых файлов подтверждается пользователем;
- что решение по крупному файлу принимает пользователь;
- что до команды `ПРИМЕНИТЬ` обычная работа не начинается, а после адаптивного старта отложенное решение блокирует только связанное с ним действие.

Отчёт должен быть коротким и понятным, без копирования всего `README.md`.

## 3. Предложи режим START

Предложи три варианта и дождись выбора:

1. **С сопровождением — рекомендуется.** Проведи пользователя по всем блокам в формате понятного теста.
2. **Быстрый.** Спроси только основные факты и отклонения, а безопасные рекомендации собери в одну сводку.
3. **Без брифа.** Проведи read-only анализ проекта, подготовь временную конфигурацию и отложи неизвестные решения до момента, когда они понадобятся.

Кратко объясни последствия каждого режима. Ни один режим не разрешает агенту самостоятельно одобрять опасные внешние действия.

## 4. Проведи настройку

Следуй `prompts/01-initialize-project.md` и охвати все 13 блоков выбранным способом.

В режиме с сопровождением каждый вопрос оформляй как карточку:

- сам вопрос;
- зачем ответ нужен сейчас или в будущем;
- 2–4 подходящих варианта с краткими последствиями;
- один отмеченный рекомендуемый вариант;
- `Не знаю / решить позже`;
- возможность дать свой ответ.

Для открытых фактов, например названия и цели, сначала предложи 1–2 формулировки по доступному контексту и разреши исправить их. Не заставляй пользователя писать текст с нуля, если можно предложить осмысленный выбор.

В быстром режиме задай только вопросы, без которых нельзя составить полезную сводку. В режиме без брифа сначала исследуй доступные файлы без изменений и самостоятельно сформируй предложения.

Не запрашивай значения секретов. Не выдумывай факты. Для каждого значимого ответа указывай источник: пользователь, файлы проекта, безопасное значение Starter Kit или отложенное решение. После итоговой сводки попроси отдельную команду `ПРИМЕНИТЬ`.
