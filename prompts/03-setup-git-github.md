# Настройка Git и приватного GitHub

Настрой Git только после завершённой инициализации проекта.

## Проверки до изменений

1. Определи фактический корень.
2. Убедись, что нет лишней вложенной папки.
3. Проверь, существует ли Git-репозиторий здесь или выше.
4. Проверь существующие remotes.
5. Проверь Git, GitHub CLI и авторизацию.
6. Проверь имя и email автора; для нового проекта предпочитай локальную настройку репозитория.
7. Проверь `.gitignore`, secret-пути и staged-содержимое.
8. Проверь размеры всех файлов до первого commit.

Если существующий репозиторий, remote или структура неоднозначны, остановись и покажи результаты.

Если Git или GitHub CLI отсутствуют, объясни требуемую установку и запроси разрешение. Для входа запусти безопасную браузерную авторизацию. Не проси токен или пароль в чате.

## Новый локальный репозиторий

- Инициализируй Git непосредственно в текущем корне.
- Используй ветку `main`, если пользователь не выбрал другую.
- Добавь все неигнорируемые файлы после проверок.
- Покажи staged-состав без раскрытия секретов.
- Создай понятный первый commit.

## GitHub

Предложи имя на основании проекта. Перед созданием и первым push покажи сводку и запроси подтверждение.

После подтверждения:

- создай отдельный приватный репозиторий;
- подключи его как согласованный `origin`;
- отправь основную ветку обычным push;
- проверь приватную видимость;
- проверь branch, remote, commit и чистоту дерева.

Не создавай публичный репозиторий, не используй force push и не перезаписывай существующий remote.

## Финальный отчёт

Укажи локальный корень, владельца и имя приватного репозитория, ветку, remote, commit, push, secret-проверку, крупные файлы и то, что остаётся вне Git.
