# Закрытие и синхронизация сессии

Этот сценарий запускается только отдельной командой `закрываем сессию`. Команда заранее разрешает документирование, commit и обычный push в согласованный приватный `origin` без повторного вопроса.

## 1. Обнови память

- Обнови `docs/STATUS.md`.
- Создай session log при наличии содержательной работы.
- Обнови changelog только при изменении, заметном пользователю.
- Создай или обнови решение только при существенном выборе.
- Обнови recovery только при изменении способа восстановления.

## 2. Выполни проверки

- Запусти согласованные проверки проекта.
- Зафиксируй успехи и ошибки.
- В персональном backup-режиме ошибка теста не блокирует сохранение, если политика не говорит иначе.

## 3. Проверь безопасность и полноту

- Проверь новые и изменённые файлы на секреты, не показывая значения.
- Проверь размер файлов до staging и commit.
- При файле от согласованного порога покажи путь, размер, тип и варианты; остановись до решения.
- Проверь, что все остальные неигнорируемые файлы будут добавлены.

## 4. Git

Продолжай автоматически только если `origin` согласован, репозиторий приватный, ветка ожидаемая, нет конфликтов и не требуется рискованная операция.

- Добавь все неигнорируемые изменения.
- Проверь staged-состав и staged diff.
- Не создавай пустой commit.
- Создай содержательное сообщение.
- Выполни обычный push.
- Проверь commit, branch, remote, push и рабочее дерево.

Остановись при секрете, крупном файле, публичной видимости, изменившемся remote, конфликте, расходящейся истории, необходимости force push, потере авторизации или отклонении GitHub.

## 5. Отчёт

Сообщи:

1. Что завершено.
2. Какие документы памяти обновлены.
3. Какие файлы добавлены, изменены и удалены.
4. Какие проверки прошли или не прошли.
5. Результат проверки секретов.
6. Результат проверки размеров.
7. Ветку, remote, commit и push.
8. Нерешённые вопросы и первый следующий шаг.
